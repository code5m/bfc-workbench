# B站收藏夹整理与同步工作台

**本地优先，真实验收，绝不绕过 B站访问保护。**

## 启动
`npm start` → http://127.0.0.1:4198 。

`npm test` 运行离线安全与接口回归测试。Node.js 20+。

## 实现范围
- 定时读取本地 JSON 快照，不调用 B站接口。
- 按 BV 号去重形成唯一视频清单，识别跨类别冲突。
- 使用标题分类和简介建议，查看全部、待复核、已有建议、失效条目。
- 在页面逐条手工确认视频分类；只存入本机 `manual-review-overrides.json`，记录本地审计日志。
- 导出 `bilibili-sync-dry-run.json`，仅供计划分析；没有真正的同步执行器。
- 读取现有熔断文件，显示 HTTP 412，禁止任何远程操作。
- 进度显示首轮 148 条历史复制；第二轮成功数在没有可信回读证据前始终为 0。

## 数据目录与权限
默认从 `~/Documents/Bilibili-Favorites-Review/` 读取，环境变量 `BILIBILI_FAVORITES_DATA_DIR` 可覆盖。

允许本地写入仅两份：
- `manual-review-overrides.json`：逐视频人工确认的主题覆盖。
- `local-review-audit.jsonl`：人工审核时间及 BV 记录。

**严禁**把个人收藏清单、Cookie、登录配置或同步日志提交 GitHub。工作台监听本机 IPv4 回环地址，审核 POST 使用同源验证、CSRF 令牌、最大 4KB JSON 请求限制。

## 验收口径
- `已生成分类` 表示建议，不代表内容已实际核对。
- `本地确认` 表示在工作台审核，不代表 B站已同步。
- `已在目标快照` 只代表本地快照存在，不能证明现在的账号状态。
- `已成功同步` 必须具备目标文件夹**实时回读**及可追溯证据。
- HTTP 412 熔断需要先通过合法正常授权流程恢复；不得切换账号/IP、规避安全验证。
- 默认禁止移动或删除旧收藏，须另行明确审批并备份。
