# 安全补采：通过保存的 B站收藏夹页面导入本地候选

此功能仅在个人设备本地运行，是 412 熔断期间的**可选离线补采通道**，不会模拟浏览器请求 B站，也不会从工作台发起收藏 API 请求。

## 当前条件

- 2026-10-13 用户表示已登录，并能在官方网页浏览默认收藏夹及翻页。这是用户报告，不是收藏 API 实时回读证明。
- 21 个收藏夹中仍有 5 个没有完成采集，默认夹历史统计 4,599，已采集 1,678，约 2,921 为历史差额（非已证实的实际余量）。
- 现有完整快照 1,991 个不同 BV；旧快照另有 64 个非当前已观察 BV，它们只有历史成员关系证据。
- 账号访问熔断 `blocked / http_412` 不解除，账号写入和远程执行器仍禁用。

## 如何使用

1. 用平时已登录的 B站官方网页，正常打开自己的一个收藏夹。**不建议自动高速翻页**。
2. 等待当前页面视频显示后，使用浏览器「另存为 → 网页，仅 HTML」得到 `.html` 文件；也可以选择原本已持有的 `.json` 视频列表。浏览器保存页可能不包含动态加载的完整收藏；每次仅以文件实际含有的 BV 为准。
3. 打开本机 [同步管理](http://127.0.0.1:4198/#sync)，找到「安全补采 · 导入已保存的网页」，选择**该文件实际对应的原收藏夹**。
4. 选择 HTML/JSON 文件，检查 BV、标题预览后点击「确认暂存到本地」。没有点击确认不会产生任何持久修改。
5. 系统将候选保存到本机 `~/Documents/Bilibili-Favorites-Review/saved-page-import-staging.json`（权限 0600），不会上传 GitHub。重复数据按 BV 去重、同一网页重复提交幂等，源收藏夹和时间可以追溯。

> 一个网页可能同时包含相关推荐。页面提取只是**本地候选**，不是经过证实的收藏关系；用户必须检查原文件来源。为了避免编造进度，本功能**不修改** `inventory-rescan-v2.json`、分类建议、人工审批或正式 B站同步记录。

## 安全与完整性约束

- 所有 HTML/JSON 都在浏览器中**按文本静态解析**，不执行脚本、不创建 DOM 图片或框架，不加载任何外部资源。
- 每批最多 200 个唯一 BV，文件最大 10MB，超过上限则拒绝（不悄悄丢弃溢出记录）。
- 只提取 BV、简要标题、原收藏夹和文件名。原网页全文、COOKIE、CSRF、SESSDATA、脚本、图片、其他个人信息都不会交给本地接口。
- 所有 POST 要求 localhost、同源 Origin、Session CSRF；导入只写本机单独的候选文件。无网页自动翻页，也不调用 B站账号写接口。
- 本地汇总显示「尚未出现在当前快照」的 BV 数量，仅代表**离线候选差额**，不代表账号增量、目前仍收藏、已审核或已同步。
- 无法通过导入网页保证完整覆盖，后续需在得到合规授权后回读全部收藏和执行正式 G1–G8 验收。

## 验收

`npm test` 覆盖文件解析、重复导入、来源追溯、字段白名单、浏览器文本解析不加载外部内容、服务器拒绝无 CSRF 请求、0600 私有保存、无账号写入等约束。

本功能是安全的补采辅助，不是全自动无风险账号采集器；无法承诺此后绝不再遇到 412。
