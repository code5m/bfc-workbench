# B站收藏整理：412 恢复及全量完成执行策略

本策略不提供绕过平台访问限制的方法，也不保证消灭 HTTP 412。

## 当前审计发现（2026-10-12）
1. 已观察 2,134 条收藏关系、1,991 个不同 BV 号；默认夹 1,678/历史报告 4,599 条，第 86 页返回 HTTP 412。
2. 21 个收藏夹仅 16 个完成分页；账号级访问保护仍为 blocked。
3. 已复制 148 条历史记录，但不代表默认夹已移出；第二轮未取得实际回读证据。
4. 旧扫描器使用固定间隔与最多 300 页作为上限，未建立正式的全账号请求预算、平台限额来源或有效的恢复授权流程。
5. 页号分页可能在用户收藏增删时发生数据漂移；即使所有页面都曾返回正常，也仍需完整对账及最终回读。
6. 曾只按返回数量终止扫描，造成错误的全量判断；已改为只按 has_more 结束。
7. 不能因处理了 1,153 条分类关系就宣称整理了同等数量的唯一 BV，也不能将历史 API 成功视为目标实时存在。

## 现在唯一允许的执行路线

### 阶段 A：纯离线（现在可运行）
- 在本地快照上去重、计算主题、复核冲突与失效视频。
- 优先处理默认夹中的已观察视频；保留来源 BV 和文件夹归属。
- 输出无网络的 dry-run 计划、风险审计和复核清单。
- 严禁工作台刷新时主动调用 B站；任何 AI agent 同样遵守 account-access-guard.json。
- 这一阶段可推进但绝不自动宣布账号已整理。

### 阶段 B：平台允许后的单次授权恢复
- 在官方网页确认账号能正常访问；检查平台认可的授权读写接口及权限。
- 在不绕过风控或验证码的前提下，人工核实授权状态。
- 解除熔断需要有明确审批和访问恢复证据，不允许依赖定时器自动解除。
- 恢复访问后统一由**一个**已授权调度器执行，禁止 15 个智能体各自发请求。

### 阶段 C：有界增量读取和完整性校验
- 采用官方声明的额度/速率；不知道额度时暂停设计写入执行，不自行假设安全请求频率。
- 逐页存盘断点与响应校验；不因返回不足一页判定结束。
- HTTP 401/403/412/429、业务风控码、验证页出现即全局熔断。
- 网络错误必须保留精确断点；不因一个目录已读取一部分就将其视为完成。
- 如平台提供可靠增量接口可使用；如仅有页号分页，完整扫描后还必须对账，避免期间增删引起的漂移。

### 阶段 D：写入、回读、默认收藏清理
- 确认视频分类与目标目录存在，对目标 BV 去重。
- 有用户授权且工具支持账号写入时才实施小批量复制；记录批次与唯一事务键。
- 每批写入后**实际回读目标**确认；回读失败不得标为成功。
- 只有完整分类和完整回读后，才在用户明确授权和恢复备份可用时考虑移出默认夹。
- 最终重新完整读取默认夹，核实所有有效视频已归类或有明确例外。

### 阶段 E：八项最终交付门禁
- 逐项检查 docs/COMPLETION_CONTRACT.md 的 G1–G8；任何一项未完成即 NOT_DONE。
- 最终证据不能由本地推测或伪造模拟值替代。

## 监督
本地 GET /api/strategy-audit 用于读取审计；不会调用 B站，也不会清除熔断。
默认文件夹始终为最高优先级。后续开发原则：**减少本地重复计算之外的远程请求，而不是寻找更隐蔽的远程请求形式**。
